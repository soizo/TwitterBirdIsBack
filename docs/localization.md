# Localization evidence

## Scope

The target is all display-language options offered by x.com, using each language's historical Twitter terminology. Coverage includes UI labels, detail headings, hover hints, native `title` and accessible labels, the translation-entry icon, and tab titles. User-authored text, display names and search queries must not be translated or rewritten.

Language resolution and translation-entry icon matching have 45-locale implementation and regression fixtures. Website terminology, title grammar and popup copy now cover the nine priority options listed below. The full 45-language inventory is not a claim of complete terminology support, nor do the priority catalogues cover arbitrary or future UI text.

Public bundle URLs for every locale are recorded in `locale-sources.json`. Captured input labels live in `../test/fixtures/x-locales.json`. Canonical aliases confirmed in the first-party bundle map include `en-gb → en-GB`, `msa → ms`, `no → nb`, `zh-cn → zh`, and `zh-tw → zh-Hant`.

## Priority implementation and limits

- Website language comes from the HTML language tag; popup language comes from the browser. The shared registry normalizes tags to existing display options. Unsupported website wording is left alone; generic trailing site branding still works.
- English and British English retain the established casing and notification rules. Other priority locales use full-string mappings in `extension/classic-locales.js`, generated by `scripts/generate-classic-locales.py`. Conflicting targets and the unrelated sports abbreviation `POST` (`bf81d3e2`) are excluded. Posting actions, heading nouns, counted labels and title templates are separate.
- The generator matches modern and historical English meanings to discover changed identifiers, then reads the corresponding first-party translations. It parses literals and a restricted concatenation/plural grammar, never executes downloaded JS, and caches by immutable resource filename. Unrecognized syntax fails generation.
- Localized notification allowlists derive from the 50 checked English notices. Two old errors require explicit identifier pairs because the historical English said “Try Retweet.” The newer highlight/boost success notices (`a50c911e`, `ie08d3a4`) retain their modern meaning and grammar, substituting only the verified historical noun. Duplicate localized strings collapse; conflicting mappings are skipped rather than guessed.
- Russian/Ukrainian counter labels preserve the original number string and retain an explicit action/state using historical words. Ukrainian noun cases use the consistent historical pressed-counter template rather than the older unpressed template's inconsistent plural. These composed accessibility labels are not claimed to be byte-for-byte historical UI strings.
- Localized text changes edit only the changed span of existing text nodes. SVGs, links, listeners and protected user text survive, including split notifications. Unknown messages and unimplemented interpolated-name templates remain unchanged. Title captures are inserted once without interpreting replacement metacharacters.

`test/priority-classic.test.cjs` and its independently recorded fixture exercise the nine options, native hints, counted states, split text, dynamic updates, title captures and protected content. These are browser tests against local page fixtures, not a claim of exhaustive live-account verification in every language.

## Official language inventory

Observed on 2026-09-08 in the display-language selector at <https://x.com/settings/language>, without saving or changing the account language: **45 options**.

```text
ar ar-x-fm bn en-gb bg ca hr cs da nl en fil fi fr de el gu he hi hu
id it ja kn ko msa mr no fa pl pt ro ru sr zh-cn sk es sv ta th zh-tw
tr uk ur vi
```

Important variants: `ar-x-fm` is Arabic (Feminine), `en-gb` is British English, and `ur` is labelled Urdu (beta). Browser HTML language tags may differ in case or canonical form from the selector values; normalize aliases explicitly rather than silently assuming they are interchangeable.

Official help distinguishes display language from the language of posts and notes that Arabic (Feminine) is web-only:
<https://help.x.com/en/managing-your-account/how-to-change-language-settings>

## Optional Grok entry-point hiding

The same 45 official locale bundles supply exact `e3eceda6` (Grok actions) and `fc7db594` (Profile Summary) labels. `isGrokLabel` trims their boundary whitespace; it never uses a broad `Grok` substring match. Additional English labels come from `h5860a68`, `dc0c8266`, `d6827e80`, `f8047ea8`, and `a3879dea`. This is current-label identification, not historical translation coverage.

Drawer and control identifiers were cross-checked against the author's [Control Panel for Twitter source](https://github.com/insin/control-panel-for-twitter/blob/master/script.js): `GrokDrawer`, `DMDrawer`, `chat-drawer-root`, `grokImgGen`, `followups_*`, and the `/i/grok` route. This is third-party selector evidence, not a fresh inspection of the user's authenticated X DOM. Icon-only controls use the observed Grok SVG prefix already captured for the translation-icon tests. Ordinary translation controls and user-content regions are excluded; `/grok` is a user profile and is not the AI route.

Both hiding options default off and use the existing refresh-only settings snapshot. Regression tests load the actual extension against local page fixtures; live account layouts may introduce additional variants.
